01实验设置

把推荐 pipeline 拆成三层——召回、规则精排、排序加权——逐个摘掉组件，看它们对最终 top-10 排序的真实贡献。这不是单元测试的替代品，而是回答「每个部件到底有没有用、用了多少」。

baseline 复刻 match_jobs_for_resume 的现行逻辑：向量召回 top 20 → 规则精排（技能 50 + 年限 20 + 地点 15 + 薪资 15）→ 方向分折半 5、地点不符降权、区命中加权 → 按 rank_score 排序取前 10。消融组只关掉对应项，其余保持不动。

召回对照的三种设定

向量余弦相似度取前 20（现行）

关键词意向标题 / 类别 / 二级方向命中后按 id 倒序取前 20，无意向则全库退化

随机每份简历固定种子洗牌全库取前 20，与向量、关键词均无关

02核心结论

一句话：向量召回是这套系统的承重墙，摘掉后 top-10 与 baseline 完全不重合，城市命中率从 44% 掉到 0，薪资覆盖率从 66% 掉到 42%，平均分从 44 掉到 24。规则层里必需技能分是最强的排序信号；薪资、地点、经验是中等信号；方向加权和加分技能分在当前数据下对 top-10 几乎没有可观测影响。

三句话带走

① 召回决定「看到哪些岗位」，规则决定「看到之后怎么排」——召回错了，规则再准也救不回来。

② 必需技能是规则层第一信号（平均挤掉 2.2 个 baseline 岗位、τ 0.77）；薪资是第二信号（挤掉 1.2 个、τ 0.76，且是唯一让薪资覆盖率下降的规则项）。

③ 方向加权在 40 人样本里对 top-10 零影响（τ = 1.0）；地点分与地点降权各管一头，只留一个都会让城市命中率下滑 7–16 个百分点。

向量召回摘掉后发生了什么

Top-10 与 baseline 重合数为 0——向量召回选出来的 20 个岗位，和关键词 / 随机选出来的 20 个，几乎是两批不同的岗位。规则精排只能在「召回给的那 20 个」里排序，召回错了，后面全错。

三个质量指标同时塌方：城市命中率 43.9% → 0%（关键词召回根本不看地点，随机召回只碰对 27%）；薪资覆盖 65.8% → 41.8%；平均匹配分 44.5 → 23.7。同时同分破缺率从 35% 涨到 76%——留下的这批岗位大多技能不匹配、分数挤在低位，排序基本失去意义。

一个反直觉的观察：随机召回的薪资覆盖率（65.3%）几乎追平向量召回，但城市命中率只有 27%、top-10 重合只有 0.5 个。说明「薪资覆盖」在 322 个岗位里不算稀缺属性（很多岗位区间本来就宽），而「城市命中」才是向量召回真正带进来的稀缺信号——它把地点相近、语义相关的岗位捞进了召回窗口。

关键词召回的城市命中是 0%，不是因为它召回的岗位都不在目标城市，而是因为意向城市没有被用作召回条件——现行 search_jobs 的关键词路径不看简历意向。这是设计缺口，不是召回算法本身的缺陷。

各分项的角色

必需技能 · 主排序信号摘掉后 top-10 换掉 2.2 个岗位，平均分从 44.5 跌到 28.0，同分破缺率升到 47.8%。它是 50 分权重里真正干活的部分。有趣的是，摘掉它之后薪资覆盖率和城市命中率反而小幅上升（69% / 53%）——技能门槛松了，地点薪资更合的岗位浮上来。这说明「技能硬门槛」和「意向满足」在这批数据里有轻微的张力：最匹配技能的岗位不一定最合薪资地点。

薪资 · 第二信号 + 主要破缺来源摘掉后 top-10 换掉 1.2 个岗位，τ 0.76，薪资覆盖率从 65.8% 掉到 60.3%——五个规则项里唯一让薪资覆盖率下降的。同分破缺率从 34.7% 涨到 53.4%，是所有单项消融里破缺最严重的：薪资分是区分「同技能水平岗位」的主要手段。

地点 · 城市命中的守门员摘掉后城市命中率从 43.9% 掉到 34.6%（-9.3 个百分点），top-10 换掉 1.3 个岗位，多样性还降了（0.69 → 0.66）。地点分不是可有可无的软偏好。

年限 · 中等信号摘掉后 top-10 换掉 0.6 个岗位，平均分掉 16 分（说明很多岗位这 20 分没拿满，即存在年限缺口），但对排序的扰动小于技能和薪资。τ 0.80。

加分技能 · 当前近乎无效摘掉后 top-10 只换掉 0.25 个岗位，τ 0.94，平均分只降 0.8 分。10 分权重在 rank_score 里被技能、地点的大分差淹没。要么提权，要么接受它只是展示层的「锦上添花」。

方向加权是死代码（在这批数据上）。去掉后 top-10 一个都没变，τ = 1.0，所有指标与 baseline 完全相同。原因：这 40 份简历里，意向方向分要么是中性 5 分（未设方向），要么命中的岗位在向量召回里本来就和技能高分岗位高度重合，折半后的 0–5 分不足以改变 rank_score 的相对顺序。如果产品上在意「设了方向的用户应该优先看到对口岗位」，当前 ×0.5 的权重不够，需要提权或改成硬过滤。

地点降权是真的在干活。去掉后城市命中率掉 7 个百分点，top-10 换掉 1 个岗位。它的作用和地点分部分重叠但不等价：地点分管「同城加分 / 异区小扣」，降权管「城市完全不符时按比例重罚」。两个都去掉（no_all_rank_adjust）和只去地点降权的结果一模一样——说明方向加权确实没有独立贡献，地点降权是排序加权层唯一的实际作用项。

06排序质量与风险

除了「哪个组件重要」，消融还暴露了几个排序质量层面的问题。

同分破缺率 35% —— 排序信息量偏低

baseline 在 top-20 里有 34.7% 的相邻岗位同分。摘掉薪资后升到 53.4%，关键词 / 随机召回下高达 76%。同分意味着顺序由 Python 稳定排序的原始顺序（岗位 id 倒序）决定——用户看到的排名有一部分是 id 运气。

这解释了为什么薪资分（连续的 0–15 区间值）比技能分（0/13.3/26.7/40 的阶梯）更能破缺。如果想降低破缺，优先精细化薪资 / 地点这类连续打分，或者引入次级排序键（如相似度、发布时间）。

技能全命中率 100% —— 召回已经把住了门槛

所有配置的 top-10 必需技能全命中率都是 100%（随机 / 关键词召回除外——那两组 top-10 里大量岗位技能不匹配，导致技能分和平均分一起塌）。向量召回实际上承担了「技能粗筛」的职能，规则层的技能分更多是在已命中的岗位之间做次级排序。这是一个健康的分工，但也意味着：向量模型对技能词的敏感度直接决定了下限。

薪资覆盖率 66% —— 还有三分之一不合期望

baseline top-10 里 34% 的岗位薪资区间与期望无交集。摘掉薪资分后升到 40%。如果产品目标包含「推荐岗位薪资要能接受」，这个数字偏高。可选手段：把薪资从「加分项」改成「硬过滤」（比如期望下限完全够不到的直接不进召回后处理）、或在 rank_score 里提权。

多样性 0.69 —— 中等集中

top-10 的公司多样性（1−HHI）0.69，即推荐不算被少数公司霸屏，但也不是充分分散。去掉地点相关项后多样性略降（0.66）——地点偏好本身在制造一定的集中度（同城公司池更小）。随机召回多样性最高（0.87）但质量最差，说明多样性不能靠放松召回来换。

08建议与边界

如果只做三件事：把意向城市加进召回过滤、给薪资加一道下限硬过滤、给方向加权换一种生效方式。其他都是打磨。

按投入产出排序的建议

1. 召回层加地点意向过滤。关键词召回城市命中 0% 不是算法问题，是召回根本不看地点。向量召回可以保留语义主通道，但在取 top 20 之前先按意向城市分桶（比如每个意向城市保底若干名额），否则异地用户的「城市命中率 44%」就是天花板。

2. 薪资从纯加分改成「下限硬过滤 + 区间内加分」。期望下限完全够不到的岗位（job_max < expect_min）直接不进精排，省下的 15 分权重用来在「能覆盖期望」的岗位里做精细排序。当前 66% 的覆盖率说明有相当一部分召回结果本来就不该出现在 top-10。

3. 方向加权要么提权、要么改成同分破缺键。×0.5 后对 top-10 零影响的组件，留着只是心理安慰。改成 rank_score 同分时的第一排序键，成本最低、至少能解决「设了方向却看到不对口岗位」的观感问题。

4. 降同分破缺。35% 的相邻同分率意味着三分之一的排名是 id 决定的。引入次级排序键（相似度、发布时间、公司多样性约束）比调权重更能改善「刷新一下顺序就变」的体验。

5. 加分技能分（10 分）可以接受现状。它对排序几乎无影响，但可能在「两个岗位其他全同」的角落场景起作用。不值得为它单独调参。

实验边界

样本是库里前 40 名有向量、有结构化技能的求职者简历，不是全体 95 人；top-10 / top-20 的指标对小样本均值敏感；「随机召回」是确定性洗牌对照，不是多次采样均值；反馈偏置未测（job_feedback 表 0 行）；薪资覆盖率用的是「区间有交集」的宽松定义，不是「完全覆盖期望」；方向加权的零影响结论仅适用于这 40 人当前的方向设置密度，如果全量用户都认真填了方向，结论可能不同。
